## 본문은 고쳤는데 예전 판이 남아 있다

비공개 레포에서 일하다 공개로 바꾸기 전에 PR 본문을 정리하는 경우가 많습니다. 내부 시스템 이름이나 경로를 지우고 저장하면 끝난 것 같지만, GitHub는 PR·이슈 본문과 댓글을 고칠 때마다 **예전 판을 수정 이력에 남깁니다.**

본문 위쪽에 "edited"가 보이면 이력이 있다는 뜻이고, 누르면 판별로 열어 볼 수 있습니다. GitHub 문서 기준으로 이 이력은 **레포를 읽을 수 있는 사람 누구나** 볼 수 있습니다. 공개 레포라면 로그인하지 않은 방문자도 포함됩니다.

## 직접 확인한 것

공개로 바꾼 레포에서 로그인하지 않은 상태로 PR 페이지를 열어 봤습니다.

- PR 본문 위에 "edited"가 보이고, 누르면 "Edited 2 times" 목록이 열립니다.
- 공개 전에 지워 둔 예전 판 두 개는 "(deleted)"로 표시되고 내용은 열리지 않습니다.
- 지우지 않은 최신 판에는 "(deleted)" 표시가 없어 그대로 열어 볼 수 있는 상태입니다.

## 지우는 방법

1. PR 본문 위의 "edited"를 눌러 이력을 엽니다.
2. 지울 판을 고릅니다.
3. 오른쪽 위 **Options → Delete revision from history**를 누르고 확인합니다.

PR 작성자나 레포에 쓰기 권한이 있는 사람만 지울 수 있습니다.

## 지워도 남는 것

- **누가, 언제 고쳤는지**는 그대로 보입니다. 지워지는 것은 그 판의 내용뿐입니다.
- 공개 전 점검 목록에 PR·이슈 본문과 **댓글**의 수정 이력까지 넣어 두는 게 안전합니다. 코드와 커밋 이력만 스캔하면 이 부분을 놓칩니다.

## 공개 전 점검에 한 줄 추가

```text
□ PR·이슈 본문과 댓글 중 "edited"가 붙은 것 → 이력의 예전 판에 내부 정보가 있으면 판 삭제
```
