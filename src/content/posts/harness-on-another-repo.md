## 무엇을 했나

AI 에이전트가 "테스트 모두 통과했습니다"라고 할 때 무엇을 믿어야 할까요? [harness-engine](https://github.com/SimSimEEE/harness-engine)은 Claude Code용 커밋 게이트입니다. 에이전트의 말을 받아 적지 않고, **실제로 무엇이 실행됐는지**를 확인한 뒤에만 커밋을 허용합니다.

이 글은 그 엔진을 엔진 자신이 아닌 다른 레포에 처음 붙여 본 기록입니다. 대상은 [mcp-safe-write-template](https://github.com/SimSimEEE/mcp-safe-write-template), AI 도구에 안전하게 쓰기 권한을 주는 MCP 서버 템플릿입니다.

## 엔진 구조: LLM은 한 칸에만 있다

1. **분류**(`classify.sh`): 바뀐 파일을 보고 어떤 검사를 돌릴지 코드가 고릅니다.
2. **검사**(`preflight.js`): 고른 검사를 LLM 에이전트들이 병렬로 실행합니다. LLM이 들어가는 곳은 여기뿐입니다.
3. **집계**: 결과를 합쳐 통과·실패를 코드가 정합니다.
4. **기록**(`receipt.sh`): 절차를 지켰는지 확인하고 통과 기록을 남깁니다.
5. **커밋 직전 훅**(`PreToolUse`): 커밋할 내용에 대한 기록이 있는지 다시 확인합니다.

무엇을 검사할지, 통과했는지는 코드가 정합니다. 기록 단계는 에이전트의 보고를 믿지 않고 **실행 기록(전사)에서 그 명령을 실제로 돌렸는지 찾습니다.**

## 이 레포에 맞춘 방법: 설치하지 않고 얹는다

엔진은 원래 사용자 전체 설정(`~/.claude`)에 설치합니다. 하지만 템플릿은 누가 클론하든 그 레포만으로 동작해야 해서, 레포 자체를 엔진의 **오버레이**로 만들었습니다.

| 엔진 기본값 | 이 레포에서 바꾼 것 |
|---|---|
| `~/.claude`에 설치 | `ENGINE_PIN`에 고정한 커밋을 받아 `.claude/` 아래 git 제외 폴더에 배치 |
| 훅이 `$HOME/.claude/hooks`에 있음 | `hook.sh` 래퍼: 엔진이 없으면 아무것도 안 하고, 사용자 전체에 이미 등록돼 있으면 비켜 줌 |
| 테스트 검사가 jest를 가정 | vitest 버전으로 덮어씀. 원본이 바뀌면 경고 |
| 기본 카테고리 `generic` | `ts-mcp-server` 카테고리: vitest, 시크릿 스캔, 변이 검사를 필수 회귀 명령으로 지정 |

그 아래에는 Claude Code 없이 도는 기본층이 있습니다. git 훅과 CI(린트, 타입 검사, 테스트, gitleaks)입니다.

Claude Code 층은 **켜야 동작**하게 했습니다(`npm run harness:setup`). 비용 때문입니다. 게이트 1회에 서브에이전트 토큰이 템플릿 첫 커밋(리뷰 포함)에서 **약 680k**, 파일 하나만 바꾼 커밋에서도 **약 150k** 들었습니다.

## 있었던 일 네 가지

### 1. 비차단 지적도 결국 다 고쳤다

게이트는 통과 판정에도 판정에 영향 없는 참고 지적을 남깁니다. 네 건이 나왔고, 같은 PR에서 모두 고쳤습니다. 예를 들면 이런 것들입니다.

- 시크릿 스캐너가 `++ `로 시작하는 추가 줄을 diff 헤더로 착각해 건너뜀
- 공백이나 한글이 들어간 파일 이름이 민감 경로 검사를 빠져나감

### 2. 검사는 통과했는데 기록이 거부됐다

가장 기억에 남는 장면입니다.

```text
게이트 기록 거부 — 분류기가 정한 회귀 명령이 실행되지 않았다: vitest, secret-scan, mutation-check
```

테스트는 정말 돌았고 통과했습니다. 그런데 카테고리에 적은 표식은 `vitest run`이었고, 실제 실행한 명령은 `npx vitest run`이었습니다. 기록 단계는 명령의 앞부분을 표식과 맞춰 보기 때문에, 이것을 실행 증거로 받지 않았습니다.

**보고가 아니라 절차를 확인하는 설계가 제 설정 실수를 잡았습니다.**

### 3. 문서를 쓰다가 막혔다

README를 셸 heredoc으로 쓰는데, 본문에 커밋 명령이 언급돼 있어서 훅이 셸 명령 전체를 커밋으로 보고 막았습니다. 오탐이지만 안전한 쪽으로 틀린 것이라 엔진은 그대로 두고, 문서는 편집 도구로 쓰도록 바꿨습니다.

### 4. 공개 전 검사: 스캐너가 안 보는 곳

레포를 공개하기 전에 빈틈이 세 군데 있었습니다.

- PR 본문(수정 이력 포함)
- 과거 커밋 이력
- CI 로그에 찍히는 파일 경로

그래서 이력 전체에서 금지어를 찾는 `--history` 모드를 넣었고, 출력에 찍히는 경로의 금지어는 `***`로 가리게 했습니다.

그 `--history` 모드에도 구멍이 있었습니다. 처음에는 파일 내용(blob) 하나당 경로를 하나만 봤는데, 같은 내용이 다른 경로에도 있으면 그 경로는 검사하지 않았습니다. 지금은 커밋마다 바뀐 경로를 전부 모아서 검사하고, 이 경우를 재현하는 테스트를 함께 넣었습니다.

## 테스트가 정말 막는지는 변이로 확인한다

안전장치 테스트가 실제로 막는지는 변이 스크립트로 확인합니다. 안전 규칙을 하나씩 일부러 깨고, 그때마다 해당 테스트가 실패해야 합니다. 사례를 처음 정리했을 때는 22개였고, 규칙이 늘면서 지금은 25개입니다. 하나라도 살아남으면 실패입니다.

```text
$ node scripts/mutation-check.mjs
...
25/25 mutations killed
```

## 정리

1. **기본층부터 깐다.** AI 없이 도는 git 훅과 CI가 바닥입니다.
2. **설치하지 말고 얹는다.** 엔진은 커밋으로 고정하고, 레포 고유 규칙은 카테고리에 둡니다.
3. **절차를 검증하게 한다.** 보고 대신 실행 기록을 읽는 게이트는 사람의 실수도 잡습니다.
4. **비용을 보이게 한다.** 켤지 말지는 숫자를 보고 사람이 정합니다.

전체 적용 기록은 템플릿 레포의 [`.claude/harness/README.md`](https://github.com/SimSimEEE/mcp-safe-write-template/blob/main/.claude/harness/README.md)에 있습니다.
